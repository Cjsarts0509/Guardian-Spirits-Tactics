# 두 기기에서 방장 이전 확인

## 자동 시험 완료 범위

실제 로컬 WebSocket과 브라우저 Worker 번들의 Node 어댑터에서 연결 종료, 프레임 보류, ACK 전달 누락을 시험한다. 뒤 두 조건은 소켓을 유지한 채 실제8초 타임아웃으로 후임에 이전한다. 장애 중 입력은 후임에서 한 번만 확정되고, 뒤늦게 도착한 구 호스트 프레임은 권한 오류로 거절된다. `apps/server/test/host-websocket.test.ts`의3조건이 통과했다. 물리 기기 절전·모바일 OS·실제 브라우저 백그라운드 정책을 시험한 결과는 아니다.

## 임시 서버

`deploy/preview-player-host.sh`를 파일로 받아 bash로 실행한다. `GST_PREVIEW_REF`는 전체40자리 커밋 SHA, 기본 포트는18787이다. 운영서비스·방화벽·설정/비밀키를 읽거나 변경하지 않고 임시 체크아웃을 빌드한 뒤127.0.0.1에서 게스트 서버를 실행한다. 빌드/실행 환경을 비워 외부 인증/저장 설정을 상속하지 않는다. 운영과 CPU/메모리를 공유한다. 설치된 소스로 시험하려면 `GST_PREVIEW_SOURCE`를 지정하고 해당HEAD와 ref 및 깨끗한 작업 상태가 일치해야 한다.

두 PC가 각각 SSH 터널을 열어 동일한 임시 서버로 연결한다. `<VM의 SSH 주소>`는 평소 VM 접속에 사용하는 주소로 대체한다. 키 인증 옵션도 평소와 동일하게 사용한다.

```bash
ssh -N -L 18787:127.0.0.1:18787 ubuntu@<VM의 SSH 주소>
```

각 PC에서 `http://127.0.0.1:18787`에 접속한다. PC A는 기존 회선, PC B는 휴대폰 테더링 등 다른 회선을 쓰면 경로 차이를 확인할 수 있다. SSH 터널 경유 시험이므로 공개 HTTPS/직접 WebSocket 배포 조건과 같지는 않다. 모바일 브라우저 자체 시험은 별도 접근 경로가 필요하다.

## 실행과 통과 기준

A/B가 서로 다른 닉네임으로 게스트 입장한다. A가 방을 만들고 B가 입장한 뒤 봇을 채워 게임을 시작한다. 처음 공개되는 각자의 캐릭터를 기록한다.

| 순서 | 조작 | 확인 |
|---|---|---|
| 1 | A가 새로고침 | B로 방장 이전, A가 같은 캐릭터로 복귀 |
| 2 | 현재 방장 브라우저 종료 후 재접속 | 남은 PC가 진행하고 복귀자가 방장을 빼앗지 않음 |
| 3 | 현재 방장 인터넷/SSH 터널 끊기 | 후임이 진행, 복귀 후 상태가 일치 |
| 4 | 방장 탭을 다른 탭 뒤로 보내30초 대기 | 계속 정상 진행하거나 멈춘 경우 후임에게 이전 |
| 5 | 방장 PC 절전20초 후 복귀 | 남은 PC로 이전, 복귀 뒤 두 방장이 동시에 진행하지 않음 |
| 6 | 전원 연결 해제 후10분 이내 재접속 | 마지막 확정 상태에서 재개; 10분 이상 빈 방은 정리될 수 있음 |
| 7 | 각 이전 직후 채팅1회 전송 | 상대에게 한 번 전달되고 게임 진행 지속 |

프레임이 멎으면 약8초 뒤 서버 타임아웃 검사에서 이전하며, 네트워크/연결 감지에 따른 추가 지연이 있을 수 있다. 백그라운드로 보냈다는 이유만으로 반드시 이전해야 하는 것은 아니다. 계산이 계속되면 기존 방장 유지가 정상이다.

결과에는 기기/OS/브라우저, 회선, 각 단계 성공 여부와 이전 시간, 중복/정체 변화/멈춤 여부를 적는다. 종료는 서버 터미널과 각 SSH 터널에서 Ctrl+C다. 운영 반영 판단은 이 결과와 원자료 대조 후 진행한다.
