# AI 개선 002회차 — 동맹 예산·보석 완성 보호

## 구현과 조건

기본 정책은 이전 후보 그대로 유지하고 개발 옵션 두 개를 추가했다. `claimGemGoal:3`은 일반 인물이 보석을 완성하기 전에 위장하지 않게 한다. 지휘관·변장 인물의 노출 예외와 필수 진명 스킬은 유지한다. `teamworkBudget:true`는 동맹 뒤 하나 이상의 유효한 즉시 확인과 확정된 아군의 필수 지원/행동 불능 해제에 필요한 마나를 남긴다. 가장 비싼 확인을 모두 예약하지 않으며 확정 공격·버닝/저주 연계의 기존 우선순위도 유지한다.

새 개발 시드 **115000–115004**, 8–12인, 4모드 × 3상대 공표 스타일 × 순서/진영 4교환 × 5정책 = **1,200실행**. 정책은 main 기준 이전 AI(baseline), PR16 기존 후보(control), 성장 보호(growth), 예산 보호(budget), 둘 다(combined)다. 같은 시드/배정의 개발 비교이며 5시드 소표본으로 승격을 주장하지 않는다.

combined는 기존 후보보다 +1.67%p지만 main 기준 AI보다 -4.17%p다. 두 수정만으로 전체 저하를 해결하지 못했다. **기본값 변경·운영 승격 없음**, 아직 독립 평가 시드는 사용하지 않았다.

황야/트롤의 동맹 직후 확인 스킬 잠재 마나 부족 사례는 기존 후보 17/14 → combined 11/9로 줄었다. 가명 턴의 보석 2단계 성장 누락은 14/13 → 0/0이 됐다. 그러나 전체 가명 성장 누락 341/494 → 333/474로 큰 차이는 없었다. 황야의 카이·샤이닝, 트롤의 데카·네오니스·치스가 대부분을 차지하며 지휘관·변장 예외의 노출/자원 교환 문제는 남는다. 마나 원시 합계·경기 길이·단방향 동맹 수입과 승패 인과를 혼동하지 않는다.

전 정책 미종료 0, 후보의 초반 공격 실패/잘못된 아군 동맹/거짓 보고 0. 전체 **464개 테스트(규칙396·서버68)**, 전체 타입 검사, 서버·화면·Worker 빌드 통과. 새 회귀 테스트는 확인 마나 보존/동맹 재허용, 확정 후계자 지원, 불필요한 예약 차단, 단계2→3 실제 턴 성장과 완성 후 위장을 검증한다.

## 실행 중 문제와 원자료

첫 실행에서 관측자의 동적 인덱스 초기화 타입 오류를 발견해 중단했다. 저장된 500실행과 당시 스크립트를 별도 보존했다. 타입 표현을 고치고 전체 1,200실행을 다시 완료했으며 중단 전 저장된 500실행은 재실행과 정확히 일치했다. 중단 자료를 최종/개발 점수에 중복 합치지 않았다.

- 원자료: `docs/evaluations/cooperation-round-002-development.json.gz`
- 독립 재집계: `docs/evaluations/cooperation-round-002-development-summary.json`
- 중단 자료: `docs/evaluations/cooperation-round-002-interrupted.json.gz`
- 당시 관측자: `docs/evaluations/cooperation-round-002-interrupted-script.ts.txt`
- 실행/검증: `packages/rules/scripts/cooperative-rounds.ts`, `tools/verify-cooperative-rounds.py`

검증기는 시드/인원/진영/순서 4교환, 승자와 점수, 행동 횟수, 역할별 턴·보석 집계, 모든 규칙 소스와 관측자/대조 정책의 SHA256을 대조한다. 코드가 바뀐 뒤 과거 자료를 검증할 때는 `--source-ref <이 회차 커밋>`을 사용한다.

## 다음 회차

기존 후보에 대한 개발 개선이 있고 안전 문제는 없지만 main 성적을 회복하지 못했다. 독립 평가를 소비하기 전에 **동맹을 받은 미확인 상대의 검증**을 우선하는 별도 후보를 개발한다. A가 B를 확인하고 동맹을 걸어도 B가 A를 모르면 안전한 보고 경로가 열리지 않는 지연을 줄이는 목적이다. 동맹 요청·공표·보고만으로 아군을 확정하지 않고 실제 확인 결과를 기다린다.
