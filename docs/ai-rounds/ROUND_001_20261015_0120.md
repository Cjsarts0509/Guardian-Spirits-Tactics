# AI 개선 001회차 — 2026-10-15

## 범위와 결정

PR #16의 고정 협력/공표 후보를 변경하지 않고 황야·트롤의 자원 비용을 관측했다. 사용자 요청에 따라 한국시간 2~6시 후속 회차와 7시 누적 보고를 예약했다. 각 회차는 최신 PR와 이 폴더의 기록을 이어받는다. main 병합·VM 배포·Supabase 변경은 하지 않는다.

## 조건과 원자료

새 개발 시드 **114000–114004**, 8–12인, 2모드 × 진명/블러프/진명 필수 스킬 보존 블러프 3상대 × 순서/진영 교환 4판 × 기존/후보 2버전 = **240실행**. 기존 최종 112000–112015를 재튜닝하거나 최종 점수에 합치지 않는다. 정책은 PR16 원본 그대로이며 관측자가 실제 정체/상태를 보는 것은 평가용 집계에만 한정한다. 봇의 입력·기억·RNG에 집계를 전달하지 않는다.

- 스크립트: `packages/rules/scripts/cooperative-economy.ts`
- 원자료: `docs/evaluations/cooperation-economy-round-001.json.gz`
- 재집계 및 코드 해시: `docs/evaluations/cooperation-economy-round-001-summary.json`
- 검증: `tools/verify-cooperative-economy.py`

## 관측

각 칸은 해당 모드의 통제 진영 60판 합계다. 마나 수치는 150 상한 적용 전 원시 지급/누락이며 순수령 차이나 승패 원인으로 해석하지 않는다.

| 관측 | 황야 기존 | 황야 후보 | 트롤 기존 | 트롤 후보 |
|---|---:|---:|---:|---:|
| 동맹 횟수 | 262 | 499 | 226 | 371 |
| 동맹 지출 마나 | 2,620 | 4,990 | 2,260 | 3,710 |
| 동맹 직후 공격 스킬 마나 부족 사례 | 7 | 14 | 7 | 5 |
| 동맹 직후 확인 스킬 마나 부족 사례 | 9 | 22 | 10 | 20 |
| 관측한 생존자 턴 | 1,039 | 1,350 | 1,323 | 1,585 |
| 진명이 아니었던 턴 | 0 | 345 | 0 | 478 |
| 진명 턴 보너스 누락 원시 마나 | 0 | 3,450 | 0 | 4,780 |
| 가명 턴에 놓친 보석 성장 기회 | 0 | 322 | 0 | 471 |
| 들어온 동맹의 원시 턴 마나 | 6,640 | 16,760 | 9,420 | 16,680 |

후보 동맹의 약 23.4%(황야)/26.1%(트롤)만 시전 당시 이미 상대에게서 동맹을 받은 상태였다. 단방향 동맹은 상대에게 소득을 주므로 나의 즉시 자원 회수와 구분해야 한다. 이후 답례 동맹·생존 효과는 이 비율에 포함하지 않는다.

동맹 지출과 확인 스킬의 잠재 차단은 늘었지만 공격 차단은 트롤에서 줄었다. 따라서 성적 저하를 전부 동맹 비용으로 설명할 수 없다. 가명 턴의 보석 성장 누락이 많이 관측됐으며 현재 공표 보호 조건의 `gem < 2`는 보석 완성 단계 3과 다르다. 단계 2에서 보석을 사용할 수 있다는 사실과 완성 단계까지 성장했다는 사실을 구분해 후속 개발할 필요가 있다. 이 회차에서는 정책을 바꾸지 않았다.

## 검증과 한계

모든 240판 종료, 시드/인원/순서/진영 교환 누락 없음. 동맹별 지출 10마나, 트레이스 기반 스킬 차단/상호 동맹 집계, 턴 마나 공식, 정책/기준/관측자 SHA256을 독립 Python 검증기로 대조했다. 타입 검사 통과. 정책·서버·UI는 바꾸지 않은 진단이므로 과거 전체 460 테스트를 불필요하게 반복하지 않았다.

스킬 마나 부족은 동맹 전에 사용 가능했고 동맹 뒤 마나가 부족해진 스킬의 존재를 뜻한다. 그 순간 실제 공격/확인을 선택했을 것이라는 인과적 증거는 아니다. 턴 수가 달라지는 두 대전의 원시 합계도 동일 길이의 마나 효율 비교가 아니다.

## 다음 회차와 시드 예약

1. 보석 단계 0/1/2와 인물별 가명 성장 손실을 나눈다. 진명 보호를 단계 3까지 유지하는 수정은 개발 시드에서 별도 후보로 비교한다. 지휘관/변장 노출의 비용도 함께 기록한다.
2. 확정 아군 동맹은 유지하되 즉시 확인/공격/필수 지원 예산을 남기는 조건을 후보로 비교한다. 단방향 동맹의 비용과 답례 수입을 구분한다.
3. A가 B를 확인했어도 B가 A를 아직 확인하지 않았다면 정보를 무조건 주지 않는다. 받은 동맹 요청자의 검증을 정보 공유 전에 우선하는 후보를 별도로 비교한다.
4. 개발 결과로 후보를 고정한 뒤 새 최종 시드를 사용하고, 최종 결과를 본 뒤 같은 자료로 재튜닝하지 않는다.

| 구간 | 용도 | 상태 |
|---|---|---|
| 114000–114004 | 001회차 자원 진단 | 사용 완료 |
| 115000–115004 | 다음 회차 개발 비교 | 예약·미사용 |
| 116000–116015 | 다음 고정 후보 독립 평가 | 예약·미사용 |

이후 회차는 실제로 사용한 구간을 이 표/후속 MD에 기록하고 새 구간을 예약한다. 7시 실행에서는 새 실험을 시작하지 않고 누적 결과와 채택/미채택을 보고한다.
