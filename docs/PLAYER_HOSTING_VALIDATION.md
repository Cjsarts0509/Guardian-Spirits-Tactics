# 방장 호스팅 검증

## 결과와 범위

방장 자동 이전을 실제 Chromium에서 확인했고 전체382개 테스트·타입 검사·웹/서버 빌드를 통과했다. 초기 구현에서 발견한 전체 로그/행동 기록 재전송과 서버의 AI 기억 복원 비용을 줄였다. 기록 추가분만 전송하고 파생 믿음 캐시는 제외하며, 서버는 지속 AI 기억을 JSON으로 보관하고 이전 때 전체 체크포인트를 만든다. AI 정책·틱 주기·행동 선택은 바꾸지 않았다.

로컬 측정에서 호스팅 전송 비용은 줄었으나 **서버 직접 계산보다 전체 CPU가 낮아졌다는 결론은 나오지 않았다**. 새 기본4방의 server/player CPU는2.53/2.69%, 고빈도4방은8.57/9.67%다. 서버 틱에 AI 계산이 없어지는 대신 프레임 수신·검증·뷰/중계 비용이 남는다. 시간 지표도 서버 틱과 호스트 프레임 확정 양쪽을 보아야 한다.

## 실제 브라우저

Chromium153.0.8010.0 headless, Linux x64/Node24.19.0, 독립 영구 프로필 두 개와 실제 웹 빌드/Worker/로컬 서버를 사용했다.7개 검사와 오류0을 [원자료](evaluations/host-browser-audit.json)에 기록했다.

- 초기 방장 워커 확정과 일반 참가자 체크포인트 미전달
- 방장 새로고침→후임 이전·원래 정체로 재접속·호스트 탈환 없음
- 이전 후 채팅1회 확정 및 상대 전달
- 후임 탭 종료→접속 중인 원래 사용자에게 이전
- 방장 자리 비움→후임 이전
- 모든 호스트 이탈 뒤 재입장·체크포인트 시계에서 재개
- 새 AI 전용 판 관전자 브라우저 호스팅

방장 표시/이전 후 게임 화면 및 AI 관전자 화면을 캡처해 한글 글꼴·배치를 확인했다. 원자료에는 캡처의 당시 임시 경로와 SHA256을 기록했다. 이미지 자체는 공개 저장소에 포함하지 않았다. 최초 표준 Chromium 다운로드가 손상 ZIP으로 실패한 뒤 별도 실행 파일과 한글 글꼴을 사용해 시험을 완료했다. 이 환경의 `--single-process`/headless 및 Playwright 기본 인자 조건이므로 모바일·백그라운드 탭 제한·서로 다른 회선·WAN 손실/지연·VM ARM 시험을 대신하지 않는다.

## 부하 측정

조건마다15초,12봇1방/12봇씩4모드4방/고빈도4방을 server와 player 순서로 각각 실행했다. 준비는 제외하고 끝난 판은 새 판으로 이어간다. 호스트 Worker는 별도 자식 프로세스에서 실행하므로 메인 CPU에 AI 계산을 포함하지 않지만 같은 머신의 CPU 경합은 남는다. 메인 CPU는 서버와 진단 드라이버의 합이며1코어100% 기준이다. 업로드는 호스트→서버 JSON 바이트 합, WebSocket/TCP 헤더 제외이고250ms IPC 보고 때문에 경계가 약250ms 어긋날 수 있다. 기본 activity0.012, 고빈도1, timeScale60이며 운영 시간/활동과 같지 않다.

각 조건은 새 무작위 판1회로 전후·계산 위치 사이 행동/생존 봇 수가 같지 않다. 숫자는 관측 결과이고 동일 부하의 인과적 개선율·장기 수용량을 뜻하지 않는다. 고빈도에서 기본4방보다 생존 봇이 적어도 연쇄 행동과 기억/기록 비용이 커질 수 있다. 측정 중 브라우저 시험·빌드·전체 테스트를 병행하지 않았다.

## 재현

의존성을 설치한 저장소 루트에서 `pnpm build` 후 브라우저 드라이버를 실행한다. Playwright 및 Chromium은 외부 QA 의존성이며 실행 경로를 설정할 수 있다. 기본 import는 `playwright`다.

```bash
GST_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
GST_CHROMIUM_EXECUTABLE=/absolute/path/to/chromium \
node apps/server/scripts/host-browser-audit.mjs > /tmp/gst-host-browser.json
```

서버 부하 진단은 운영 서비스/비밀키를 사용하지 않고 임의 로컬 포트에서 실행한다. 소요시간은 준비를 제외하고 기본90초다.

```bash
cd apps/server
node --import tsx scripts/host-load-audit.ts 15000 > /tmp/gst-host-load.json
```

## 운영 반영 전 남은 확인

- 수신한 Node22 ARM VM 반복 콘솔의 상세 원자료/해시 대조와 긴 판의 누적 체크포인트 크기.
- 서로 다른 회선의 두 사람에게 새로고침/종료/복귀와 입력 지연을 확인.
- 모바일·백그라운드/절전·느린 호스트에서8초 무응답 이전과 게임 진행 확인.

PR10은 AI PR9을 기준으로 한 별도 초안이다. main/운영 릴리즈/VM은 변경하지 않았다. 운영 bootstrap은 이 브랜치를 설치하지 않는다.

VM용 반복 진단 실행기와 결과 명령은 [PLAYER_HOST_VM_AUDIT.md](PLAYER_HOST_VM_AUDIT.md)에 있다. 새 실행기는 같은 소스의 server/player를 AB/BA/AB 순서로 측정하며 기존 표의 숫자를 새 드라이버 측정값으로 바꾸지 않는다.

사용자 ARM VM 콘솔 결과와 해석은 [PLAYER_HOST_VM_AUDIT.md](PLAYER_HOST_VM_AUDIT.md), 체크포인트 구성의 로컬 후속 진단은 [PLAYER_HOST_TRANSPORT_FINDINGS.md](PLAYER_HOST_TRANSPORT_FINDINGS.md)에 있다.
