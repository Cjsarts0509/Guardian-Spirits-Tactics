# 상대 대응 포함 탐색 실험

PR #9의 `attackSearch` 실험에 `attackResponse` 옵션을 추가했다. 두 옵션 모두 기본은 비활성화다.

각 가설의 기본 스킬을 유지하고 공격 등급, 스캔, 텔레포트, 시간 해금의 교체 관계를 정리한다. 관측된 데카의 방어 패시브 해제도 반영한다. 이는 공격/방어에 필요한 일부 관계 보정이며 모든 조건부 flags와 도달 가능한 게임 이력의 증명이 아니다.

상대 대응은 가설 엔진에서 상대 자기 뷰와 수신 가능한 이벤트만 사용한다. 실제 상대 기억이나 역할 배정 전체를 정체 지식으로 넣지 않는다. 확인된 적을 대상으로 이름 공격만 고른다. 마나·쿨다운·사용 횟수·행동 불능·보호 상태·스킬 사전 조건은 엔진이 검사한다. 각 상대가 한 대응 시점에 최대 한 번 공격하는 스트레스 조건과 대기 조건을 비교한다. 확률이나 완전한 상대 전략 예측이 아니다.

최대 128회 시뮬레이션한다. 다음 턴 1ms 전까지만 진행해 복원하지 않은 턴 마나/자동 공표를 결과에 섞지 않는다. 실제 예약 효과·공격 이외의 상대 스킬·비공개 상대 기억·조건부 방어 flags는 아직 복원하지 않는다.

## 첫 개발 결과

`node --import tsx scripts/response-search.ts 20 31000` (`packages/rules`에서 실행).
같은 개발 시드 20개, 진영/순서 교환, 4모드 320판. 운영 정책 대비 전체 점수 45.9375%, 시드 부트스트랩 95% 구간 43.59375–48.125%. 내전 50%, 태초 45%, 황야 50%, 트롤 38.75%. 트롤 2판은 90분 제한 미종료이며 0.5점으로 반영했다. `evaluations/response-search-development.json`은 이 첫 버전의 소스 해시를 보존한다. 개선 판정 실패다.

2,400개 공개 정체 합성 위치의 로컬 중앙값 15.16ms, p95 26.34ms, 최대 45.63ms. 후보 없는 호출도 포함한다. 실제 VM이나 라이브 호출 분포의 측정이 아니다. `evaluations/response-search-audit.json`은 첫 버전 원자료다.

전체 309개 테스트, 타입 검사, 클라이언트/서버 빌드를 통과했다. 상대의 미확인 대상 공격 금지, 쿨다운/마나/보호/행동 불능, 교체 관계, 입력/RNG 보존 및 128회 상한을 확인했다. 테스트 성공은 대전 성능 향상을 의미하지 않는다.

후속 보완 대상은 후보 상한으로 기존 정책의 공격이 빠지는 문제, 반복 대기, 대응 계산의 중복 비용이다. 개발 결과를 보고 보정한 뒤 새 시드로 독립 검증한다. 기본 활성화 또는 운영 병합은 개선과 비용 검증 통과 이후다.
