# 상대 대응 포함 탐색 실험

이 문서는 이름 공격 대응 단계의 개발·독립 검증 기록이다. 이후 별도 옵션으로 추가한 즉사기·행동 불능기 대응과 새 시드 검증은 `BOT_ACTIVE_RESPONSE.md`를 참고한다.

PR #9의 `attackSearch` 실험에 `attackResponse` 옵션을 추가했다. 두 옵션 모두 기본은 비활성화다. 현재 독립 검증 결과로 운영 정책보다 개선됐다고 판단할 수 없어 초안으로 유지한다.

각 가설의 기본 스킬을 유지하고 공격 등급, 스캔, 텔레포트, 시간 해금의 교체 관계를 정리한다. 관측된 데카의 방어 패시브 해제도 반영한다. 이는 공격/방어에 필요한 일부 관계 보정이며 모든 조건부 flags와 도달 가능한 게임 이력의 증명이 아니다.

상대 대응은 가설 엔진에서 상대 자기 뷰와 수신 가능한 이벤트만 사용한다. 실제 상대 기억이나 역할 배정 전체를 정체 지식으로 넣지 않는다. 확인된 적을 대상으로 이름 공격만 고른다. 마나·쿨다운·사용 횟수·행동 불능·보호 상태·스킬 사전 조건은 엔진이 검사한다. 각 상대가 한 대응 시점에 최대 한 번 공격하는 스트레스 조건과 대기 조건을 비교한다. 확률이나 완전한 상대 전략 예측이 아니다.

최대 128회 시뮬레이션한다. 다음 턴 1ms 전까지만 진행해 복원하지 않은 턴 마나/자동 공표를 결과에 섞지 않는다. 실제 예약 효과·공격 이외의 상대 스킬·비공개 상대 기억·조건부 방어 flags는 아직 복원하지 않는다.

## 첫 개발 결과

`node --import tsx scripts/response-search.ts 20 31000` (`packages/rules`에서 실행).
같은 개발 시드 20개, 진영/순서 교환, 4모드 320판. 운영 정책 대비 전체 점수 45.9375%, 시드 부트스트랩 95% 구간 43.59375–48.125%. 내전 50%, 태초 45%, 황야 50%, 트롤 38.75%. 트롤 2판은 90분 제한 미종료이며 0.5점으로 반영했다. `evaluations/response-search-development.json`은 이 첫 버전의 소스 해시를 보존한다. 개선 판정 실패다.

2,400개 공개 정체 합성 위치의 로컬 중앙값 15.16ms, p95 26.34ms, 최대 45.63ms. 후보 없는 호출도 포함한다. 실제 VM이나 라이브 호출 분포의 측정이 아니다. `evaluations/response-search-audit.json`은 첫 버전 원자료다.

전체 309개 테스트, 타입 검사, 클라이언트/서버 빌드를 통과했다. 상대의 미확인 대상 공격 금지, 쿨다운/마나/보호/행동 불능, 교체 관계, 입력/RNG 보존 및 128회 상한을 확인했다. 테스트 성공은 대전 성능 향상을 의미하지 않는다.

첫 버전의 소스는 원격 커밋 `10612acce0e94971840a3985f8434290dde911a5`에 보존했다.

## 후보 보존 및 지휘관 방어 평가 보완

기존 정책이 고른 합법적인 공격은 최대 3개 후보에 반드시 포함한다. 점수가 같으면 기존 선택을 유지한다. 확인 제약을 어긴 baseline 인자는 후보로 추가하지 않는다. 통합 정책에서 탐색이 대기를 고르면 기존 공격을 유지해 불완전한 가설로 반복 공격 취소를 하지 않는다. 첫 행동·대응·시간 진행은 후속 후보 사이에 재사용한다.

횟수 보호는 보호받는 대상의 남은 공격 횟수에 포함한다. 지휘관의 생명·보호 횟수·데카의 방어용 마나 감소를 대상 가치(지휘관 20, 일반 4)와 초기 남은 공격 횟수로 정규화해 평가한다. 사망은 기존 대상 가치, 승리/패배는 ±1000으로 평가한다. 마나형 방어는 마나 25당 공격 1회를 버티는 실제 규칙을 따른다. 이 점수는 확률이나 실제 상대 자원 관측값이 아니다.

| 개발 단계 | 운영 정책 대비 전체 점수 | 미종료 |
| --- | ---: | ---: |
| 첫 상대 대응 버전 | 45.9375% | 2 |
| 기존 후보 보존·반복 대기 방지 | 48.4375% | 0 |
| 지휘관 방어를 남은 공격 횟수로 평가 | 49.6875% | 0 |

세 단계는 동일한 개발 시드 31000–31019를 사용했으므로 독립 표본이 아니다. 원자료는 `response-search-{development,rerank-development,effort-development}.json`에 단계별 소스 해시와 함께 보존했다. 후보 보존 단계는 `4df64a74e577bbfea7a743369e3b3b386153aa27`, 최종 평가 코드는 `db09ae0b1860b751270eeb7062c93c74b5134734`에 보존했다.

## 고정 코드 독립 검증

최종 코드를 고정한 뒤 새로운 시드 34000–34099, 8–12인, 진영/순서 교환으로 네 모드 1,600판을 평가했다. `node --import tsx scripts/response-search.ts 100 34000`. 기준은 같은 최신 규칙 엔진의 운영 행동 정책 `fe4ccaa`이며 탐색 옵션을 끈 정책이다.

| 모드 | 승/패 | 점수 | 시드 부트스트랩 95% 구간 |
| --- | --- | ---: | --- |
| 내전 | 200 / 200 | 50% | 50–50% |
| 태초 | 200 / 200 | 50% | 50–50% |
| 황야 | 198 / 202 | 49.5% | 48.5–50.5% |
| 트롤 | 199 / 201 | 49.75% | 48.75–50.75% |
| 전체 | 797 / 803 | 49.8125% | 49.4375–50.1875% |

모든 판이 종료했다. 독립 단위는 개별 판이 아니라 시드 블록이다. 내전/태초의 정확히 50%는 이 고정 대전 구성에서의 결과이며 인간 상대 동률이나 두 정책의 완전한 동등성을 의미하지 않는다. `evaluations/response-search-heldout.json`에 원자료·설정·소스 해시를 저장했다. 운영 정책보다 개선됐다는 근거가 없다. 검증 결과를 본 뒤 추가로 정책을 수정하지 않았다.

최종 코드 311개 테스트, 타입 검사, 클라이언트·서버 빌드 통과. 후보 보존과 지휘관 보호 소진 회귀 테스트를 추가했다. `response-search-effort-audit.json`은 2,400개 합성 위치에서 입력/RNG 보존과 128회 상한을 확인한다. 로컬 중앙값 14.55ms, p95 29.24ms, 최대 110.13ms이며 다른 평가/빌드가 동시에 실행됐다. 앞 단계와 비용 향상률로 비교하면 안 되고 VM 지연도 아니다.

## 남은 범위

비용 재측정은 `response-search-effort-audit-repeat.json`에 보존했다. 로컬 중앙값 13.90ms, p95 20.65ms, 최대 51.13ms다. 대전/빌드는 같이 돌리지 않았지만 초반 타입 검사가 겹쳤다. 장비와 실행 부하 영향을 받는 참고 수치이며 VM 성능 판단에 사용하지 않는다.

독립 검증 이후 황야 34009·트롤 34046의 교환 대전 8판을 진단했다. 기존 공격 대신 다른 대상/스킬 선택 5번, 공격 대신 대기 0번이었다. `response-search-trace.json`은 최대 100개 차이와 소스 해시를 담는다. 이는 검증 후 진단이며 추가 정책 튜닝이나 독립 성능 검증이 아니다. 변화가 있는 사례를 일부 조사한 것이므로 전체 대전의 변경 빈도를 추정할 수 없다.

공격 이외의 상대 액티브 스킬, 확인 후 공격 연계, 지연 효과/예약 작업, 조건부 flags, 조건부 획득의 전체 상관관계가 빠져 있다. 공개/비공개 수신 이벤트로 검증 가능한 부분부터 확장해야 한다. 계산 비용도 별도 서버 부하 검증이 필요하다. 개선과 비용 검증을 통과하기 전 기본 활성화 또는 운영 병합을 하지 않는다.
