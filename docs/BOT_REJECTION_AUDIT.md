# 조건부 행동 거절 진단

판단 지연 개선 정책 `2796a617`(원격 `ff2c188d`)을 그대로 사용했다. 정책·엔진·실험 옵션 기본값은 변경하지 않았다. 진단 스크립트의 평가자 전용 상태는 정책 입력이나 봇 기억에 전달하지 않는다.

## 결과

새 시드 66000–66009, 4모드, 8–12인, 좌석 순서/진영 교환 4조건으로 총 160판을 실행했다. 양측은 동일 확장 정책(`sequenceSearch`, `sequenceSkills`, `sequenceExtended` 활성화)을 사용했다. 운영 기본 정책 또는 인간 상대 승률 평가가 아니다.

| 항목 | 결과 |
| --- | ---: |
| 종료 | 160 / 160판 |
| 행동 시도 | 10,318회 |
| 거절 | 14회 (약 0.136%) |
| 비공개 보호로 거절 | 14회 |
| 공개 보호 / 기타 사유로 거절 | 0 / 0회 |
| 초반 4분 공격 실패 | 0회 |

거절 스킬은 진실의 보석 8회, 상급 스캔 4회, 전사의 감각 2회였다. 모두 엔진의 `대상이 보호받고 있어 지정할 수 없습니다.` 오류였다. 평가자가 확인한 활성 보호의 출처는 모두 `rune_protection`이었다. 행동 직전 자기 뷰에는 해당 대상의 보호 상태가 없었고, 사용 스킬은 사용 가능·남은 쿨다운 0이었다. 원자료를 별도 검사해 각 분류와 관찰 기록을 대조했다.

## 판단과 한계

기존 정책은 공개된 무적 상태를 제외하며, 동맹 선택에서도 본인의 동맹 목록을 확인한다. 인물 후속 스킬은 공개 보호와 `ignoresInvulnerable`을 함께 확인한다. 엔진은 대상 보호와 사전 조건을 검사한 뒤 비용·쿨다운을 지불하므로 이번 보호 거절은 자원·횟수·쿨다운을 소비하지 않는다.

이 표본에서 자기 관찰로 예방할 수 있는 선택 오류는 발견하지 못했다. 대상의 비공개 효과를 정책에 넣어 거절을 없애면 정보 은닉을 깨므로 그런 변경은 하지 않았다. 행동 거절 결과는 현재 봇 기억으로 전달되지 않으며, 그 피드백을 활용하는 전략은 별도 설계·평가가 필요하다. 거절 0을 보장하거나 이전 평가의 모든 거절 원인이 같다고 일반화하지 않는다.

평가자는 행동 직전 `viewFor(state, actor)`를 저장하고, 행동 적용 뒤 실패만 기록한다. 평가자 전용 실제 효과는 별도 필드에 보존한다. 새 진단은 기존 1,600판 승률 평가를 대체하지 않으며 새로운 승률 개선 자료도 아니다.

전체 351개 테스트(규칙 332 + 서버 19), 타입 검사, 서버·클라이언트 빌드 통과. 이번 변경은 진단 드라이버와 보고서이며 운영 배포가 필요한 정책 변경은 없다. PR #9 초안에 반영하고 main·운영 릴리즈·VM은 유지한다.
