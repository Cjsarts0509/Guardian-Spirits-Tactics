# 봇 AI 기반 정비 — 2026-10-06

확률 믿음 엔진을 붙이기 전, 관찰의 정확성과 플레이어별 기억을 정비한다.

## 관찰과 확정 제약

- `Fact.character`: 실제로 확정할 수 있는 정체.
- `Fact.not`: 관찰에서 확정할 수 있는 부정 정보.
- `Fact.oneOf`: 진명과 변장/위장을 구별할 수 없을 때의 후보 집합. 실제 변장 여부를 메타데이터로 알려주지 않도록 진짜 성공과 거짓 성공에 동일하게 붙인다.
- 이름 오류와 보디가드의 공격 실패에는 같은 데이터만 제공한다. 숨겨진 판정 원인으로 후보를 삭제하지 않는다.
- 후보가 하나면 한 사람당 한 역할이라는 배정 규칙으로 정체를 추론한다. 추론은 원래 관찰과 분리하여 매번 계산한다.

클라이언트의 기존 확정 정체 표시는 `character` 만 사용하므로 변장 가능한 성공을 확정 정체 카드로 표시하지 않는다. 관찰의 원래 성공 문구는 유지한다.

## 기억과 입력 경계

`createBotMemory(seed)` 는 한 판의 한 플레이어 전용이다. 서버·시뮬레이터·스마트 봇 테스트 모두 플레이어별 인스턴스를 사용한다. 서버는 게임 시작 시 인간 플레이어의 봇 대행용 기억도 따로 만든다. 재접속·대행 전환 때는 해당 플레이어의 기억을 유지하고, 다음 갱신에서 밀린 개인 이벤트를 처리한다.

`updateBotKnowledge(view, events, memory)` 는 자신의 뷰와 수신 가능한 이벤트만 사용한다. 수신자를 한 번 더 검사하고 마지막 처리 seq 이후의 제약만 누적한다. 세례·족장 보호·블러디 매드니스 상태와 공격 실패 이력도 기억한다. 전체 서버 상태나 다른 봇의 기억은 보관하지 않는다.

`botKnowledge` 는 기존 호출 호환용 서버 어댑터다. 기억을 생략하면 전체 재계산하며, 기억을 주면 `eventsFor` 의 커서 조회로 증분 처리한다. 동일한 관찰의 숨겨진 배정을 바꿔도 같은 지식·행동을 만드는 회귀 테스트를 유지한다.

실패 원인은 추측하지 않되, 같은 후보 수·공격 가능 비율인 대상 사이에서는 최근 실패하지 않은 대상을 먼저 고른다. 무적 대상 지정 가능 여부는 `SkillView.ignoresInvulnerable` 로 노출하여 중화의 주술과 일반 공격을 구분한다.

## 평가

명령: `pnpm sim -- 300 0 smart <civil_war|primordial|lidellut|troll>`.
인원 8~12 순환, 게임 시드 1000~1299, 250ms 틱, 행동 확률 0.012. 봇별 난수 시드는 `77 + 판 번호 + 플레이어 번호 * 997`.

| 모드 | 진영 1 / 진영 2 / 미종료 | 중앙값 | p90 |
|---|---|---|---|---|
| 내전 | 158 / 142 / 0 | 10.3분 | 13.8분 |
| 태초 | 171 / 129 / 0 | 12.7분 | 17.2분 |
| 황야 | 139 / 161 / 0 | 9.2분 | 12.5분 |
| 트롤 | 87 / 212 / 1 | 12.0분 | 19.6분 |

전 모드 초반 4분 공격 실패 0건. 트롤 seed 1201은 90분 제한까지 미종료: 치스·즈윈라·데카만 남아, 즈윈라의 공격 비용·데카의 마나 회복과 블러디 매드니스가 맞물려 정체된다. 다음 행동 가치·자원 계획 단계의 재현 사례로 유지한다. 시뮬레이터는 미종료 시드를 출력한다.

플레이어별 난수와 정당한 관찰 처리가 바뀌었으므로 과거 공유 난수 봇의 승률과 단순 비교하여 강화 효과를 주장하지 않는다. 혼합 버전 평가 리그와 Brier 기록은 다음 단계다.

## 다음 단계

1. 전체 배정 파티클과 약한 행동 증거, Brier 평가.
2. 확인 결과가 다음 행동을 바꾸는 가치, 공격 위험·마나 계획.
3. 같은 시드·자리/진영 교환·혼합 상대 리그.

기존 판 기록의 변장 성공·공격 실패 `facts` 는 예전 엔진의 숨겨진 정보를 포함할 수 있다. 학습 자료는 당시 전체 로그를 그대로 봇 입력으로 쓰지 않고, 호환 가능한 행동 기록을 수정된 엔진으로 재생해 플레이어별 관찰을 재구성해야 한다.
