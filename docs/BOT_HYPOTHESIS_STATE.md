# 가설 자원·방어 상태 구성

## 진행 상태

전체 정체 배정 표본을 자기 관찰에 맞는 자원 범위로 변환하는 기반을 구현했다.
짧은 전투 롤아웃, 확인 이후 공격/보호/대기 결과 비교, 실제 행동 선택 연결은
아직 구현하지 않았다. 이번 단계의 추가 승률 개선을 주장하지 않는다.

`hypothesisWorld(view, knowledge, battle, assignment)`는 실제 GameState를 복사하지 않는다.
배정의 사람 수·역할 유일성·자기 정체·공개 역할 목록·확인 제약을 검사하고,
자기 뷰와 관찰된 스킬 기억만 사용한다.

| 항목 | 자신 | 다른 사람 |
| --- | --- | --- |
| 마나 | 자기 뷰의 정확한 값 | 0–150 |
| 스킬 | 현재 보유 스킬·패시브·사용 불가 사유 | 공개 역할 정의와 조건부 가능 목록, 존재 여부 0–1 |
| 쿨다운 | 현재 남은 시간 | 관찰 기준 하한부터 규칙 쿨다운까지 |
| 사용 횟수 | 현재 남은 횟수 | 0부터 관찰된 최소 사용을 뺀 최대 횟수 |
| 목숨 | 자신의 현재 추가 목숨 | 생존 시 1부터 현재 규칙의 역할별 최대 목숨까지 |
| 보디가드 횟수 | 자기 flags의 값 | 태초의 쿠마린/컨슘에 대해 0–2, 관찰된 소모로 상한 축소 |
| 공표 일치 | 자기 진명 상태 | 가설 정체와 공개 공표의 일치 여부 |
| 효과·flags | 자기 뷰의 효과와 flags | 공개 상태 효과만, 실제 숨은 flags는 제외 |

카즈로우는 광폭화 초기화가 가능하므로 과거 사용만으로 쿨다운 하한을 고정하지 않는다.
관찰된 쿨다운은 모든 비공개 행동을 안다는 뜻이 아니다. 상대의 남은 마나나
실제 패시브 획득을 확정하지 않으며 관찰된 목숨 추정도 현재 정확한 HP로 복사하지 않는다.

`hypothesisScenarios`는 적 자원/방어가 강하고 아군이 약한 경우 및 그 반대의
범위 끝점을 만든다. 자기 값은 두 시나리오에서 같다. 이 시나리오는 스트레스 검사용이며
실제 상태나 확률 50:50을 뜻하지 않는다. 스킬 교체/획득의 상관관계나 모든 사전 조건을
검사한 도달 가능한 엔진 상태도 아니다. 후속 롤아웃 어댑터는 이런 관계를 추가로 처리해야 한다.

현재 API는 행동 정책에서 호출하지 않는다. 실제 상태 복제나 가설 정체의 확정 기억
되돌려쓰기를 금지한다. 반환 데이터는 별도 객체이며 수정이 자기 뷰나 확인 기억에 영향을 주지 않는다.

## 검증

4개 모드, 8–12인, 시드 30000–30019, 시점 0/120/400/800초에서 10,240개
가설 상태와 20,480개 끝점 시나리오를 구성했다. 모든 범위가 유한한 비음수이고
하한이 상한을 넘지 않는지, 자기 상태가 끝점에 따라 바뀌지 않는지 검사했다.
이는 전투 결과나 승률 실험이 아니다. 결과와 소스 해시는 `hypothesis-audit.json`에 보관한다.

회귀 테스트는 자기 값 보존, 상대의 실제 숨은 마나/스킬/목숨 변경에 대한 동일 관찰
불변성, 중복/확인 제약 위반 거절, 관찰된 쿨다운과 초기화 가능성 보존을 검사한다.

```bash
# packages/rules에서
node --import tsx scripts/hypothesis-audit.ts
```
