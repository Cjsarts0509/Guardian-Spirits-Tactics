# 확인 정보의 후속 공격 활용도

## 평가 경계

확인 스킬이 줄 수 있는 관찰 결과를 역할 확률로 묶는다. 일반 확인과 스캔은
성공/실패, 보석은 개별 정체/지휘관 묶음으로 분류한다. 결과별 후보가 하나가
되는 경우에만 해당 정체에 대한 후속 공격 가치를 더한다. 지휘관 둘이나 변장
후보가 묶이는 관찰을 확정 정체로 계산하지 않는다. 기존의 정보 없는 공격 차단도 유지한다.

자신의 이름 공격이 현재 사용 가능하고 확인 뒤의 마나로 시전할 수 있어야 한다.
상대의 추가 목숨과 관찰된 보디가드 횟수는 `estimatedHits`로 반영하며,
생존 보디가드에 의한 영구 보호는 공격 가치에서 제외한다. 관찰된 상대의
스킬 사용 횟수와 쿨다운 범위를 `roleThreat`에 반영한다. 준비된 적의 위협과
지휘관 가치를 더하고 필요한 공격 횟수로 나눈 실험적 점수다.

이 점수는 성공을 보장하지 않는다. 상대의 숨은 마나, 추가 비공개 스킬 사용,
모든 조건부 패시브와 미래의 자원 회복까지 시뮬레이션하지 않는다. 전문 즉사기나
조건부 공격 대신 자신의 이름 공격만 후속 활용 대상으로 평가한다. 전체 배정
표본과 엔진 롤아웃도 아직 구현하지 않았다. 입력은 자신의 뷰, 정당한 관찰 기억과
배정 확률이며 실제 상대 상태를 복사하지 않는다.

## 실험 옵션

기본 정책은 검증한 황야 한정 후보다. `false`는 기존 확인 선택 비교용이다.

- `confirmationSearch: true`: PR6의 정보량/마나/쿨다운 비교.
- `'combat'`: 확인 비교와 보석 대상에 후속 공격 가치를 추가.
- `'combat-gem'`: 보석 대상만 변경하여 영향을 분리.
- `'combat-lidellut'`: 황야에서만 `'combat'` 적용, 나머지는 기존 확인 선택.

## 정책 선택 절차

운영 기준은 고정 `b95a326`이다. 시드마다 동일 배정에서 두 진영과 두 순서를
교환한 4판을 수행하고, 네 모드의 시드별 평균을 전체 점수로 사용한다.
8–12인, 250ms 틱, 행동 확률 0.012, 90분 제한을 유지한다.
95% 구간은 시드 블록을 2,000회 재표본화한다.

1. 23000–23029: 전체 적용, 보석만 변경, 이전 자원 비교 정책과의 비교를 각각 480판 수행.
2. 24000–24099: 전체 적용을 운영/이전 확인 정책 각각과 1,600판 비교.
3. 25000–25099: 위 결과로 고른 황야 한정 후보를 새로운 1,600판으로 검증.
4. 26000–26199: 3단계 구간이 50%에 걸쳐 있어 후보를 고정하고 별도 3,200판을 최종 확인.

단계별 시드와 코드 해시를 JSON에 보관한다. 여러 정책이 같은 시드를 공유하므로
총 판 수를 독립 표본 수로 해석하지 않는다. 마지막 실험 이후 추가 조정은 하지 않는다.

## 중간 결과

| 정책/기준 | 시드 수 | 전체 점수 | 95% 구간 |

| 보석만 변경 / 운영, 개발 | 30 | 46.0417% | 42.9167–49.1667% |
| 전체 적용 / 이전 확인, 개발 | 30 | 45.6250% | 42.0833–49.1667% |
| 전체 적용 / 운영, 검증 | 100 | 48.8750% | 47.1250–50.6875% |
| 전체 적용 / 이전 확인, 검증 | 100 | 47.7500% | 46.2500–49.4375% |
| 황야 한정 / 운영, 새 검증 | 100 | 50.9375% | 50.0000–51.8750% |

전체 적용의 운영 대비 모드 점수는 내전 40.75%, 태초 51%, 황야 56%, 트롤 47.75%다.
내전의 악화가 크므로 전체 적용은 기각한다. 보석만 변경한 개발 실험에서도 내전
손실이 나타났다. 즉시 공격 활용도가 장기 승리 가치를 충분히 대변하지 못한다는
해석은 가설이며, 특정 패시브나 행동이 손실의 원인이라고 확정하지 않는다.
황야 한정 후보의 새 검증은 황야 53.75%, 나머지 세 모드 각각 50%였다.

## 최종 판정

고정한 황야 한정 후보를 새 시드 26000–26199의 3,200판으로 확인했다.

| 범위 | 현재 승/패 | 점수 | 시드 95% 구간 |
| --- | --- | ---: | --- |
| 전체 | 1,646 / 1,554 | 51.4375% | 50.71875–52.1250% |
| 황야 | 446 / 354 | 55.7500% | 52.8750–58.5000% |
| 내전 | 400 / 400 | 50.0000% | 50.0000–50.0000% |
| 태초 | 400 / 400 | 50.0000% | 50.0000–50.0000% |
| 트롤 | 400 / 400 | 50.0000% | 50.0000–50.0000% |

모든 판이 종료했다. 전체 구간이 50%를 넘으므로 황야 한정 후보를 기본 정책으로
승격한다. 모든 모드의 개별 개선이나 인간 상대 승률 개선을 주장하지 않는다.
전체 적용과 보석만 변경하는 정책은 실험 옵션으로 남고 기본값에 적용하지 않는다.

선택 후보와 기본값은 네 모드의 행동/RNG 비교와 동일 3,200판 재실행으로 검증한다.
동일 시드를 재실행한 결과는 추가 독립 표본으로 계산하지 않는다. 최종 후보와
기본값 결과는 각각 `confirmation-combat-lidellut-final.json`과
`confirmation-combat-production-final.json`에 보관한다.

이번 단계는 개발/검증/최종 후보 9,440판과 기본값 재현 3,200판을 실행했다.
중간 검증으로 정책을 골랐으므로 24000 결과와 25000 결과를 최종 26000 결과에
합쳐 신뢰구간을 좁히지 않는다.

## 재현

`packages/rules`에서 실행한다. 각 결과 파일의 해시에 맞는 스냅샷을 사용한다.

```bash
node --import tsx scripts/confirmation-combat.ts 30 23000
node --import tsx scripts/confirmation-combat.ts 30 23000 production gem
node --import tsx scripts/confirmation-combat.ts 30 23000 search
node --import tsx scripts/confirmation-combat.ts 100 24000
node --import tsx scripts/confirmation-combat.ts 100 24000 search
node --import tsx scripts/confirmation-combat.ts 100 25000 production lidellut
node --import tsx scripts/confirmation-combat.ts 200 26000 production lidellut
node --import tsx scripts/confirmation-combat.ts 200 26000 production default
```

첫 개발 스냅샷은 원격 `dcaf1be8`이며, 영향 분리와 24000 검증 스냅샷은
`0926927a`, 황야 한정 선택은 `3fc2fd97`이다. 각 JSON의 SHA-256이 실행 소스의
일치 여부를 확인한다. 이전 단계 JSON은 해당 단계의 코드에 고정되어 있으므로
최신 파일과 해시가 다를 수 있다.

이 평가는 합성 봇 대결의 승패를 측정한다. 인간 상대 승률, 실제 서버 처리 시간,
지연이나 메모리 사용량을 측정한 결과로 해석하지 않는다.
