# 관찰 기반 수순 탐색의 판단 지연 개선

수정 전 기준은 로컬 `34398ab` / 원격 `778a6f8e36f869176ba5fdd51d8b7cea4da64b04`다. 새 정책 가중치·탐색 예산·실험 옵션 기본값은 변경하지 않고 반복 계산을 줄였다. 모든 정책 파일의 SHA-256과 평가 스크립트 해시는 원자료에 보존했다.

## 병목과 변경

로컬 CPU 프로파일에서는 가설 대응의 `updateBotKnowledge` → `observeBattle` → `roleSkills` 호출이 반복됐다. 특히 한 확인 이벤트가 여러 확인/스캔 스킬 후보를 가진 경우, 스킬마다 전체 역할 목록을 다시 계산했다.

1. 한 이벤트에서 역할별 잠재 스킬 목록을 한 번만 계산한다. 이벤트가 끝나면 캐시를 버리므로 이후 스킬 획득·제거·시간 해금이 그대로 반영된다. 스킬 정의의 전체 객체 복사도 제거하고 같은 모드 우선순위로 조회한다. 후보 순서는 유지한다.
2. 가설 속 상대 대응은 매번 새 기억을 만들고 반환 정체 지식만 사용한다. 그 기억의 사용하지 않는 전투 이력 수집을 생략했다. 정체 facts·수신자 필터·변장 대안·공표·후보 소거는 모두 처리한다. 대응 시 사용 가능 여부는 기존처럼 해당 가설 플레이어 자신의 슬롯·마나·쿨다운·사용 횟수와 실제 엔진 판정을 따른다. 실제 봇의 지속 기억은 기본값으로 모든 스킬·패시브·쿨다운 관측을 기록한다.

## 의미 보존 검증

- 기본 정책 80조건과 확장 정책 80조건, 합계 160조건을 각각 수정 전/후에 실행했다(320회 엔진 실행). 4개 모드, 8–12인, 새 시드 64000–64004의 좌석/진영 교환을 포함한다. 결과 객체와 모든 시도 행동의 시각·시전자·내용·허용 결과·수신 이벤트가 일치했다. 기본 5,230회 + 확장 5,098회 = 10,328회 행동을 비교했다.
- 동일 합성 800위치의 전체 정책을 세 번씩 비교했다. 2,400개 행동 선택 및 실제 봇의 지속 기억이 모두 일치했다. 추가로 800위치의 수순 반환값(탐색 생략 포함), 반환 시 점수·시뮬레이션 수·후속 평가/캐시 횟수가 일치했다. 입력 상태·관찰 기억 보존을 확인했다.
- 스킬 교체 뒤 새로운 공격 쿨다운을 기록하는 회귀, 일회성 기록 생략에서도 변장/개인 facts가 같은 정체 지식을 만드는 회귀, 타인의 개인 facts 수신 차단 회귀를 추가했다.
- 전체 351개 테스트(규칙 332 + 서버 19), 타입 검사, 서버·클라이언트 빌드 통과. 로컬 전체 테스트의 pnpm 실행기가 버전 전환 경로 오류로 시작되지 않아 같은 규칙/서버 Vitest 전체 스위트를 직접 실행해 검증했다. 프로토콜/클라이언트는 기존과 같이 별도 테스트가 없다.

이 검증 범위에서 의미 차이를 발견하지 않았다. 모든 가능한 게임 상태의 동등성 증명이나 새로운 승률 개선 자료로 사용하지 않는다. 이전 1,600판 승률 결과는 당시 고정 정책의 역사적 결과로 유지한다.

## 비용 측정

다른 대전/검사 프로세스가 끝난 뒤 로컬 Node `v24.19.0`에서 측정했다. 새 시드 65000–65004, 마나 100·전원 진명 공표 조건의 동일 800위치에서 수정 전/후 실행 순서를 교차했고 같은 위치를 3회 반복했다. 각 조건 200위치 × 3회 = 600표본이다. 별도 워밍업 표본을 제외하지 않았다. 아래는 반복 표본을 합친 분위수이며, 600개 독립 위치를 뜻하지 않는다. 측정 뒤에 내부 수순 결과 검증을 분리해 실행했다.

| 관측 조건 | 중앙값 이전 → 현재 | p95 이전 → 현재 | 최대 이전 → 현재 |
| --- | ---: | ---: | ---: |
| 정체 비공개 / 턴 50초 전 | 0.37 → 0.35ms | 31.97 → 21.35ms | 61.04 → 52.44ms |
| 정체 공개 / 턴 50초 전 | 0.16 → 0.15ms | 0.32 → 0.29ms | 14.60 → 13.14ms |
| 정체 비공개 / 턴 10초 전 | 0.36 → 0.35ms | **51.53 → 29.97ms** | **95.62 → 49.35ms** |
| 정체 공개 / 턴 10초 전 | 0.16 → 0.15ms | 0.33 → 0.34ms | 14.77 → 13.29ms |

정체 비공개·턴 직전의 합친 p95는 약 42% 감소했다. 각 반복의 p95도 `54.17→32.36`, `50.77→29.29`, `49.48→29.50ms`로 모두 낮아졌다. 다른 시드에서 측정했던 이전 보고서의 54.40ms와 직접 빼지 않는다. 정체 공개·턴 직전의 합친 p95는 소폭 증가했다. 따라서 모든 조건이 빨라졌다고 해석하지 않는다.

합성 위치의 실험 정책 비용이며 실제 운영 호출 분포·VM ARM Node 22·동시 12인 봇 부하는 측정하지 않았다. 비용 신뢰구간은 계산하지 않았다. 전체 판단의 중앙값 변화는 작고, 목표로 삼은 비공개 조건의 긴 지연이 줄었다.

## 반영 범위와 VM

코드·회귀 테스트·재현 드라이버·결과를 PR #9 초안에 반영한다. 실험 탐색 기본값은 계속 false이고 main·운영 릴리즈·VM은 변경하지 않았다. 이번 목표는 실험 탐색의 지연을 줄이는 것이므로 현재 운영 VM을 업데이트할 단계는 아니다. 실제 봇 기억에도 역할 목록 계산 개선이 적용되는 코드지만 운영 설정의 비용 감소 폭을 따로 측정한 자료는 없다.

VM 업데이트 명령은 해당 변경이 main에 병합되고 Release의 새 빌드가 완료된 뒤 제공해야 한다. 현재 `bootstrap.sh`는 기존 latest 운영 빌드를 내려받으므로 이번 변경을 검증하기 위한 업데이트 명령으로 쓰면 안 된다. 운영 반영 단계에서는 버전 확인과 전체 봇 부하 실측을 함께 진행한다.

원자료: `docs/evaluations/sequence-latency-compatibility.json`, `sequence-latency-cost.json`.

```bash
# packages/rules에서. 수정 전 소스는 34398ab 고정 체크아웃이다.
node --import tsx scripts/sequence-latency-compatibility.ts /path/to/34398ab/packages/rules/src/bot.ts
# 대전/검사 종료 후 비용 측정과 내부 결과 비교
node --import tsx scripts/sequence-latency-cost.ts /path/to/34398ab/packages/rules/src/bot.ts
```
